# Demon's Souls launcher — Electron (Windows)

- **Latest-only runtime:** `_Build/latest/native-build/kyty_emulator.exe` and `_Build/latest/native-build/kyty_shader_precompile.exe`. Failed Stage7/probe variants are no longer selectable. Uses upstream dynamic `KYTY_READ_GUARD` policy; do not force PAGE_GUARD above 20 GiB RAM.
- **Resumable shader update:** `Update Missing Shaders` leaves a `.resume-required` marker through interrupted merges and will re-plan unfinished shaders instead of falsely recording a complete fingerprint.

Small two-window PC game launcher styled after classic Sony PC setup dialogs. The window opens with **Play / Options / Quit** and the installed game's own art. Options uses native-feeling controls with **Display, Graphics, Advanced, Shader Cache** tabs; Discord configuration is JSON-only. No backend service, no external CDN.

- **Play** invokes the project's existing `run-windows.ps1` with the selected emulator executable.
- **Options** edits the same `../launcher-settings.json` as the previous Windows launcher.
- **Performance / Balanced / Quality** change render height, quality and upscaler, while preserving independently chosen **Frame Generation** (Off or 2x–6x), RAM16 and RAM Diet settings. 2x requests `-FrameGen 1` from `run-windows.ps1`; the actual native emulator must have NVIDIA Streamline SDK headers at compile time to support DLSS and DLSS-G.
- **Distance Tessellation (Original / Early Fade, experimental):** Separate opt-in test for Demon's Souls PPSA01341 v1.07. Early Fade only replaces the shipped PS5 Performance render profile's `+r_tessellationFadeOutStart=12.0` with `10.0`, through the emulator's temporary virtual-read copy, keeping tessellation density, fade range, and recursion untouched. Original is the default and clears stale inherited environment settings. Only the exact original profile and exact game version qualify; all other cases fail closed. Works alongside the existing DLSS/FSR PS5 Pro display-mode rewrite without changing output mode or game files. Its units, visual effect, performance benefit and runtime acceptance are unverified; compare images and frametimes before using it for normal play. No shader precompile is triggered by choosing it.
- **Distance Detail (Original / Balanced / Performance / Aggressive):** Separate **Demon's Souls engine LOD choice** and sunlight shadow cutoff without changing internal render resolution or texture budget. Original (the default for existing installs) makes no changes. Balanced = LOD-height 1080 / 200 m sun shadows; Performance = 720 / 125 m; Aggressive = 480 / 60 m. Native `KYTY_DISTANCE_DETAIL` is injected through the existing runner's `-Set` switch and applied *after* the normal `KYTY_GAME_CONVARS` from Graphics Detail, using the loader's last-value-wins behavior. This is **not real geometric distance culling, VRS, or object-specific LOD**. Low/Lowest Graphics Detail may still disable nearby ambient/spot shadows and reduce texture detail; choose Standard Graphics Detail if those near effects matter. The preset mode and Frame Generation remain independent. No new shader precompile/cache invalidation is required from this flag alone; FPS/stutter improvements are not guaranteed.
- **RAM Safety Mode (ON for new installations; existing saved values are preserved):** Uses the single latest native executable. Native shader prefetch pauses under RAM pressure (4096 MiB guard), limits background shader workers, adjusts safe retirement of stale textures, and allows normal writeback of sparse-file guest pages. **The experimental Stutter Guard was removed**: this setting no longer changes pipeline-eviction age, batch size, remake cooldown, or forces pipeline eviction under host RAM pressure. Driver pipeline eviction follows the separate RAM Diet/VRAM policy. The already-known dangerous scene-only mass sweep remains suppressed while RAM Safety is On, to avoid reintroducing the older stutter regression. This is not a hard RAM cap and does not guarantee protection against blue screens.
- **Game output (1080p, 1440p or 4K):** The newest chenxiao native runtime supports PS5 Pro DLSS/FSR paths at the chosen output height. 1080p output requires 16:9. Check image quality and HUD alignment during gameplay.
- **DLSS / Frame Generation:** graphics presets keep your selected FG multiplier. Start with **Frame Generation 2x** (saved as `framegen: 2`, passed as `-FrameGen 1`); Off is `framegen: 0`. The Windows emulator itself must be built with Streamline headers, not merely launched with its runtime: CMake reads the configured SDK path from `launcher-settings.json` when the default source SDK folder is absent. The game's startup log must confirm Streamline/DLSS; if it says `this build has no Streamline support`, even DLSS SR is falling back to game TAA. RTX 40/50 FG additionally needs OS/GPU/driver support; observe the `Frame generation:` lines in `_Build/run-logs` and check Windows HAGS if rejected. FG adds input latency and is not guaranteed to work for every game frame.
- **Update Missing Shaders** first securely checks upstream `chenxiao07/KytyPS5` for the game's version-specific published hints (GitHub Contents API, size and Git blob digest validation); if changed, safely replaces them and retains the previous hints as a backup. When the upstream check is offline/unavailable, it keeps local hints and logs the fallback. Base `.seeds` are created when absent; a new game extraction requires explicit `-RefreshSeeds` and is not triggered merely by an executable rebuild or a game-folder move. Then the button starts a tracked incremental run. A separate Shader Update window shows real-time phase, elapsed time, processed/running/waiting shards, and a scrollable live log. Use **View Progress** to reopen it. **Stop after current shards** requests cooperative cancellation: running shards finish and their results merge; nothing kills the cache writer mid-merge. Each update has a log under `_Build/run-logs/launcher-shader-updates`. Closing the progress window does not stop the update.
- **Protected shader inputs:** Shader Cache lists seeds (base and derived), published/release hints including backups, recorded-play hints, file manifests, render-pass states and the cache fingerprint, with source directories. **All are KEEP/locked**; neither the UI nor backend allows their deletion, including if they are found inside an archived cache group. Only unrelated, explicitly safe cache groups remain selectable for Recycle Bin. The old `.seeds.program` marker is also preserved for safety.
- **Content-based precompile skip**: after a compatible incremental run, a SHA-256 fingerprint records game seeds, release hints, render pass states and shader source plus cache file identity. Later timestamp-only changes can be ignored **only if** native GPU/driver identity and translator-feature stamp still match and there are no pending shards. Unknown fingerprints, packaged installs without sources, incompatible drivers or changed shader sources fall back to native incremental checking. The first clean incremental check establishes a fingerprint without compiling pipelines.
- **Mods Manager (Options → Mods):** select an imported mod and use **Inspect Files** for a read-only SHA-256 inventory (REPLACE / ADD / IDENTICAL / CONFLICT / INVALID; or RESTORE / REMOVE for active mods). Enable/Disable repeats preflight before confirmation. The accepted directory format and restrictions are documented in [Mods Manager format](../docs/MODS_MANAGER_FORMAT.md). Import an extracted mod folder or ZIP with game-relative asset directories (e.g. `textures/`, `characters/`, `ui/`). Imports are **disabled by default** and are copied into ignored `_Mods/packages` outside the installed game. Enable asks for confirmation, checks conflicts and saves verified copies of every replaced original asset under `_Mods/originals`. Disable restores originals; if external edits are detected it blocks restoration rather than destroy those edits. New files introduced by the mod are removed on disable. Disabled packages can be removed from the mod library. A write-ahead journal and **Repair Incomplete Change** protect against interrupted operations. ZIPs are extracted through a bounded, path-validated PowerShell extractor; executable/script, `eboot.bin`, PRX and `sce_sys` modifications are prohibited. All mod actions are refused while the emulator or shader updater is active. Asset-file replacement only: no automatic repacking, script injection, Nexus integration, load-order conflict overwrite, or game-specific validation. Installing shader-affecting mods may require rebuilding corresponding shaders, and should be tested with a backup of your own game.
- **Steam Non-Steam Game integration (Advanced → Set Up Steam):** shows the packaged EXE target and `--steam-game` Launch Options for Steam → Games → Add a Non-Steam Game. Launching that shortcut auto-starts Demon's Souls, keeps the Steam-launched Electron process alive while the `run-windows.ps1 -Follow` game session runs, and exits after the session. It does not change your launcher settings or create Steam userdata files. Steam displays the shortcut's Non-Steam Game title while active, not Discord-style Steamworks Rich Presence. Steam Overlay/Steam Input may vary with process injection, and achievements are not available. Existing Discord RPC remains JSON-only and independently opt-in. Details in [Steam integration guide](../docs/STEAM_INTEGRATION.md).
- **Shader Cache** distinguishes the active (undeletable) cache, completed saved versions (older/newer and switchable), old unfinished shards (not switchable), and auxiliary shader data. **Save Current Version** copies the complete active GPU binaries to `_PipelineCache/generations` (requires disk space). **Use this version** changes the real active binary files only while KytyPS5 is closed, verifies GPU/driver support and rolls back if invalid. It always retains the previously active cache as a selectable version. No versions are created or deleted automatically.
- **Cleanup safety labels** are enforced by the backend: **SAFE TO CLEAN** for interrupted archived shards (selectable), **BACKUP — REVIEW** for non-active saved generations / old driver backups (selectable with a specific warning), and **DO NOT DELETE / KEEP — PERFORMANCE** for the active cache and driver/warmup/file/precompile caches (not selectable, deletion rejected at IPC). Nothing is deleted automatically. Eligible files are moved to Windows Recycle Bin after confirmation.
- **Discord Rich Presence (JSON-only / opt-in):** Discord configuration is intentionally **not visible in any launcher tab**. Set `discord_presence`, `discord_app_id`, and optional `discord_large_image` in the root `launcher-settings.json` as shown below. Create a Discord application named `KytyPS5` at https://discord.com/developers/applications and copy its Application ID; the displayed app name comes from Discord, not this executable. As soon as the launcher opens, Discord shows **Running KytyPS5** / **In launcher • Ready to play**. When `kyty_emulator.exe` starts, it switches to **Running KytyPS5** / **Playing Demon's Souls Remake** with elapsed time. Its detached local IPC agent survives closing the launcher, stops after the emulator process exits, and retries when Discord is launched later. No login token, bot, external server, or UI configuration is required.

### Configure Discord only in `launcher-settings.json`

Edit these properties within the existing JSON object, keeping other graphics and game settings unchanged (do not paste a second JSON object):

```json
{
  "discord_presence": true,
  "discord_app_id": "123456789012345678",
  "discord_large_image": "demons_souls"
}
```

Replace the sample ID with **your** Discord Application ID (17–20 digits). `discord_large_image` is an optional asset key uploaded in your Discord application's Rich Presence Assets; use `""` to disable the image. To disable Presence, set `"discord_presence": false`. Save the JSON before opening the launcher (or reopen the launcher after editing). All other Settings operations preserve these values even though there is no Discord UI. Presence is sent when enabled with a valid Application ID and either the launcher or game is running. Run `npm run discord:diagnose` from `launcher-electron` to check local Discord IPC (handshake only); inspect `_Build/run-logs/discord-presence.log` to see whether Discord acknowledged your status.
- **Cancel** restores the settings snapshot from when the dialog was opened, including immediately saved preset choices.
- Monitor selection and separate anti-aliasing are disabled, since the current emulator does not provide those independent controls.

## Development

```cmd
cd launcher-electron

npm start
```

## Windows executable
```cmd
npm run build
```
The build converts the installed game's `sce_sys/icon0.png` into the Windows executable, window and taskbar icon (16–256 px). Game artwork is not committed or distributed. On machines without an installed game (e.g. CI), the build generates a generic sword-and-ring fallback icon instead of the old K. Override the source with `KYTY_GAME_ICON` if needed.

The only packaged Launcher is at `../_Build/latest/launcher/DemonsSoulsLauncher-win32-x64/DemonsSoulsLauncher.exe`; keep its Electron companion files together. Older launcher versions are no longer supported.
